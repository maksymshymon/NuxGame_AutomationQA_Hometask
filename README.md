## Тест-кейс

**TC-01. Успішне перемикання мови інтерфейсу авторизованим користувачем (English → Українська)**

| Поле | Значення |
|---|---|
| Компонент | Special:Preferences → User profile → Internationalisation |
| Пріоритет | High |
| Середовище | https://en.wikipedia.org, Desktop Chrome |
| Тестові дані | Мова: `uk · українська`; стаття: `Facebook` |

**Передумови**

1. Існує зареєстрований акаунт Wikipedia.
2. Користувач авторизований на https://en.wikipedia.org.
3. Поточна мова інтерфейсу користувача — `en · English`.

**Кроки**

| # | Дія | Очікуваний результат |
|---|---|---|
| 1 | Відкрити https://en.wikipedia.org/wiki/Special:Preferences | Відкрита сторінка із заголовком **Preferences** |
| 2 | Перейти на вкладку **User profile** | Вкладка **User profile** активна, на ній є розділ **Internationalisation** |
| 3 | У розділі **Internationalisation** у полі **Language** ввести `uk` і вибрати зі списку `uk · українська` | У полі відображається `українська`, кнопка **Save** стала активною |
| 4 | Натиснути **Save** | Налаштування збережено, сторінка Preferences перезавантажилася |
| 5 | Переглянути сторінку Preferences | Інтерфейс українською: заголовок **Налаштування**, активна вкладка **Особові дані**, розділ **Інтернаціоналізація**, кнопка **Зберегти**; у полі мови збережено `українська` |
| 6 | Відкрити статтю https://en.wikipedia.org/wiki/Facebook | Вкладки дій зі статтею українською: **Читати**, **Обговорення**, **Переглянути історію** |

**Постумова:** повернути мову інтерфейсу `en · English`, щоб акаунт повернувся у вихідний стан.

## Що саме перевіряється

> [!IMPORTANT]
> Налаштування **Preferences → User profile → Language** змінює лише мову **інтерфейсу** користувача, а не мову вмісту статей.

Мова статті залежить від розділу Wikipedia (en.wikipedia.org завжди показує статті англійською) і перемикається окремо, на сторінці статті. Тому тест **не перевіряє вміст статті**: він може бути іншою мовою, ніж обрана в налаштуваннях.

Натомість тест перевіряє елементи інтерфейсу:

- на сторінці Preferences: заголовок, назву вкладки, назву розділу, кнопку збереження;
- на сторінці статті: вкладки дій зі статтею (**Читати**, **Обговорення**, **Переглянути історію**).

Повний список рядків, які перевіряються для кожної мови, наведено у файлі [test-data/languages.ts](test-data/languages.ts).

## Як тест-кейс реалізовано в автотесті

Усе, включно з логіном, передумовами й постумовою, тест робить через UI, без прямих запитів до API.

1. **Логін** ([tests/auth.setup.ts](tests/auth.setup.ts)) виконується один раз в окремому setup-проєкті: тест відкриває головну сторінку, натискає **Log in** у шапці, вводить логін і пароль на `auth.wikimedia.org` і чекає повернення на головну. Стан сесії (cookies) зберігається у `playwright/.auth/user.json` через `storageState`, тому основний тест стартує вже авторизованим.
2. **Передумова 3** (`beforeEach`): через сторінку Preferences виставляється English. Якщо мова вже English, нічого не змінюється. Так тест не залежить від стану, в якому його залишив попередній прогін, навіть якщо той упав.
3. **Кроки 1–6** ([tests/change-interface-language.spec.ts](tests/change-interface-language.spec.ts)) оформлені як `test.step`, тому у звіті видно, на якому саме кроці сталася помилка.
4. **Постумова** (`afterEach`): мова повертається на English, навіть якщо тест упав.

Кілька технічних рішень:

- **Page Object Model.** Робота зі сторінками винесена в [pages/](pages), тож тест описує лише сценарій.
- **Локатори.** Вони прив'язані до стабільних `id` MediaWiki (`#mw-prefsection-personal-i18n`, `#prefcontrol`, `#ca-view`…), а не до тексту, бо ту саму сторінку тест перевіряє двома мовами.
- **Послідовний запуск.** Мова інтерфейсу — це налаштування одного спільного акаунта, тому тести йдуть в один потік (`workers: 1`).

## Підготовка

Для тесту потрібен акаунт Wikipedia. Креди передаються лише через змінні оточення (`process.env`); файл `.env` у git не потрапляє.

```bash
cp .env.example .env
```

Заповни `.env`:

```dotenv
WIKI_USERNAME=your_username
WIKI_PASSWORD=your_password
```

> [!NOTE]
> Тест змінює мову інтерфейсу акаунта і наприкінці повертає English. Краще використовувати окремий тестовий акаунт.

## Запуск у Docker

Потрібен лише Docker (з Docker Compose v2), Node.js на хості не потрібен.

```bash
docker compose run --rm --build e2e
```

або через npm-скрипт:

```bash
npm run docker:test
```

Що відбувається:

- образ збирається на базі `mcr.microsoft.com/playwright:v1.63.0-noble`, у якому вже є браузери і всі системні залежності. Версія образу має збігатися з версією `@playwright/test` у `package.json`;
- креди передаються в контейнер під час запуску з `.env` (`env_file`) і не зберігаються в образі (`.env` є в `.dockerignore`);
- папки `playwright-report/` і `test-results/` змонтовані з хоста як volume, тому HTML-звіт одразу з'являється в локальній папці проєкту, а контейнер після прогону видаляється (`--rm`).

## Локальний запуск

Потрібен Node.js 20+.

```bash
npm ci
npx playwright install chromium
npm test
```

Інші корисні команди:

| Команда | Що робить |
|---|---|
| `npm run test:headed` | запуск із видимим браузером |
| `npx playwright test --ui` | UI-режим Playwright для налагодження |
| `npm run typecheck` | перевірка типів TypeScript |

## Звіт

Після кожного прогону (і локального, і в Docker) HTML-звіт лежить у папці **`playwright-report/`** в корені проєкту.

Відкрити звіт:

```bash
npm run report
```

або відкрити файл `playwright-report/index.html` у браузері напряму.

Для тестів, що впали, у звіті є скриншот, відео і trace (`test-results/`). Trace можна відкрити просто зі звіту.

## Можливі проблеми

| Симптом | Причина і рішення |
|---|---|
| `WIKI_USERNAME and WIKI_PASSWORD must be set` | немає `.env` або змінні в ньому порожні, див. [Підготовка](#підготовка) |
| `Failed to load .env: no such file or directory` (Docker) | Docker Compose не знайшов `.env` у корені проєкту |
| `Cannot connect to the Docker daemon` | Docker не запущений |
| `read-only file system` (Docker) | закінчилося місце на диску; звільни місце, перезапусти Docker і почисти кеш: `docker builder prune` |
| setup падає на очікуванні повернення на головну | неправильний логін або пароль; подивись скриншот у звіті |
